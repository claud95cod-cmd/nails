## 2026-11-25 · Доступность записи

Для клиента и ручной записи шаг старта по умолчанию составляет 60 минут. При определении занятости учитывается вся длительность услуги с дополнением. Поэтому один 90-минутный визит может закрывать два часовых старта. Подтверждено на локальном сайте после обновления базы с одним сохранённым визитом.

## 2026-11-25 · Проверки PostgreSQL на Windows

Путь проекта содержит кириллицу. При запуске переносимого initdb из этой папки создание кластера UTF-8 завершалось ошибкой кодировки. В tests/run_local.py исполняемые файлы и системные SQL-файлы копируются в одноразовую папку TEMP с латинским путём. PostgreSQL слушает только loopback. Подтверждение — успешный сквозной прогон пяти тестов, включая Chrome и конкурентное бронирование.

## 2026-11-25 · Импорт и восстановление экземпляра

Пустой экземпляр создаётся через `python -m storage --empty`. В `python -m starter` файл настроек и фото проверяются до записи, а повторный импорт в заполненный экземпляр отклоняется. У каждой витрины собственные база, каталог фото и ключи доступа. В прогоне `tests/run_local.py` две витрины проверены в Chrome, запись и тестовый push остались во второй. Для проверки восстановления использован холодный снимок временного PostgreSQL и отдельный архив фото. Встроенный Windows PostgreSQL не поставляет pg_dump и pg_restore.

## 2026-11-25 · Бесплатный HTTPS и проверка PWA

Для сервера без постоянного диска выставляйте `MEDIA_STORAGE=postgres`. Импорт и загрузка сохраняют обе версии фото в схеме booking, поэтому при обновлении веб-сервиса папка с фото не нужна. В SQL для Supabase Cron вызов обработчика ограничен случаями, когда очередь содержит готовые доставки. Режим хранения и обработчик очереди проверены локально в прогоне из 11 тестов. Chrome зарегистрировал service worker при открытии кабинета, имитация нажатия на уведомление передала ссылку на визит, и после входа открылась эта карточка. Для проверки системного показа требуется физический телефон.
