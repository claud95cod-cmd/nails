# Онлайн-запись

Демонстрационный профиль, одна услуга, часы 10–18 по Астрахани. Приватные данные хранятся в схеме booking. Прикладные секреты создаются отдельно для каждого экземпляра.

## Docker Compose

Из корня проекта, с установленными Python 3.12 и Docker Compose:

```sh
python -m pip install -r requirements.txt
python configure.py
docker compose --profile local up -d --wait db
docker compose build
docker compose run --rm web python -m storage
docker compose up -d web worker
```

Открыть http://localhost:8000 и http://localhost:8000/admin. Пароль задаётся интерактивно, configure.py создаёт новый .env и отказывается перезаписывать существующий. Для телефона нужен публично доверенный HTTPS на обратном прокси. Для путей /v/ и /admin исключить параметры и приватные URL из журналов прокси. Приложение запускается с отключённым access log.

С внешней БД добавить DATABASE_URL в .env, пропустить запуск db и выполнить оставшиеся команды. Для облака использовать строку PostgreSQL с TLS. При обновлении выполнить сборку, инициализацию схемы и запуск web и worker. Сохранить прежние .env, имя проекта Compose и тома базы и фотографий.

## Второй экземпляр на том же сервере

Из корня проекта один раз соберите общую версию приложения.

```sh
docker build -t nail-studio:local .
```

Создайте второй экземпляр с отдельной базой, томом фотографий, паролем и ключами push. Команда запрашивает пароль и email владельца. Стартовый комплект содержит вымышленную студию ресниц.

```sh
python configure.py instance iva --port 8001 --url http://localhost:8001 --starter starter-kit/profile.json
```

Кабинет открывается по адресу `http://localhost:8001/admin`. Редактор находится в разделе «Настройки → Профиль, услуги и портфолио». Если убрать `--starter`, команда создаст пустую витрину. Повторное создание с тем же идентификатором останавливается. Каждый экземпляр слушает свой локальный порт. Для внешнего адреса настройте отдельный HTTPS-домен на обратном прокси и укажите этот домен в `--url`. Для проверок двух кабинетов в одном браузере используйте разные хосты или два профиля браузера, поскольку cookie одного хоста действуют на всех его портах.

Комплект можно импортировать в существующий пустой экземпляр через `python -m starter путь/к/profile.json` в окружении этого экземпляра с нужными `DATABASE_URL` и `MEDIA_DIR`. Фотографии задаются относительно файла комплекта. Поле `portfolio[].service` — номер услуги в списке, начиная с 1. JPEG, PNG и WebP ограничены 8 МБ и 24 мегапикселями на фото.

При обновлении соберите новый общий образ один раз. Если тег меняется, укажите его в `APP_IMAGE` каждого экземпляра. Повторите эти две команды для каждого имени проекта и файла настроек.

```sh
docker compose -p booking-iva --env-file instances/iva/settings.env --profile local run --rm --no-deps web python -m storage --empty
docker compose -p booking-iva --env-file instances/iva/settings.env --profile local up -d --no-build web worker
```

## Резервная копия и проверка восстановления

Для согласованной копии на время выгрузки приостановите приём записей и изменения в кабинете. Храните архивы базы, фото и файл настроек в защищённом хранилище. Файл настроек содержит секреты.

```sh
docker compose -p booking-iva --env-file instances/iva/settings.env --profile local exec -T db pg_dump -U master -d master -Fc -f /tmp/master.dump
docker compose -p booking-iva --env-file instances/iva/settings.env --profile local cp db:/tmp/master.dump ./master.dump
docker compose -p booking-iva --env-file instances/iva/settings.env --profile local exec -T web tar -C /var/lib/booking-media -cf /tmp/media.tar .
docker compose -p booking-iva --env-file instances/iva/settings.env --profile local cp web:/tmp/media.tar ./media.tar
```

Для проверки подготовьте отдельную пустую БД PostgreSQL и отдельный каталог фото. Восстановите дамп командой `pg_restore --dbname=ИМЯ_ТЕСТОВОЙ_БАЗЫ --no-owner master.dump` и распакуйте `media.tar` в этот каталог. Запустите только веб-процесс с тестовыми `DATABASE_URL` и `MEDIA_DIR`. Сверьте витрину, миниатюру, крупное фото и сохранённый визит. Обработчик push для восстановленной тестовой копии должен быть остановлен.

## Бесплатный запуск для приёмки · Render и Supabase

Render Free даёт HTTPS-адрес и запускает FastAPI. Supabase Free хранит записи, очередь и обработанные WebP-фото в PostgreSQL. Фото занимают место в общем лимите базы 500 МБ. У Render первый запрос после 15 минут простоя может ждать около минуты. Supabase может приостановить проект после недели низкой активности. Для приёмки используйте вымышленные контакты. [Ограничения Render](https://render.com/docs/free) · [Тарифы Supabase](https://supabase.com/pricing)

1. Создайте отдельный проект Supabase Free. В **Connect** возьмите строку **Session pooler** на порту 5432 и добавьте `sslmode=require` к параметрам. Вставьте пароль БД в строку согласно формату URI. Схему `booking` не добавляйте в Supabase Data API. [Подключение к PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres)
2. В PowerShell из корня проекта создайте отдельные секреты для хостинга и инициализируйте новую базу. Введите строку подключения в скрытом поле. Если нужен пустой профиль для заполнения через кабинет, пропустите импорт комплекта.

   ```powershell
   python configure.py --env-file .env.render
   $connection = Read-Host 'Строка DATABASE_URL с TLS' -AsSecureString
   $env:DATABASE_URL = [System.Net.NetworkCredential]::new('', $connection).Password
   $env:MEDIA_STORAGE = 'postgres'
   python -m storage --empty
   python -m starter starter-kit/profile.json
   Remove-Item Env:\DATABASE_URL, Env:\MEDIA_STORAGE
   ```

3. Подключите свой Git-репозиторий к Render и создайте **Blueprint** по `render.yaml`. Передайте `DATABASE_URL` из Supabase и значения `ADMIN_HASH`, `SESSION_SECRET`, `CRON_SECRET`, `VAPID_EMAIL`, `VAPID_PUBLIC`, `VAPID_PRIVATE` из `.env.render` через форму Render. Файл секретов храните локально. После запуска откройте `/healthz`, витрину и `/admin`. При повторном развёртывании сохраняйте базу и ключи VAPID. [Blueprint Render](https://render.com/docs/infrastructure-as-code)
4. В Supabase включите расширения `pg_cron` и `pg_net`. В **Vault** создайте секреты `booking_url` со стабильным HTTPS-адресом без завершающей косой черты и `booking_cron_secret` со значением `CRON_SECRET`. В SQL Editor выполните `supabase-push.sql`. Задача каждую минуту проверяет очередь и делает HTTP-вызов, когда есть доставки к отправке. [Supabase Cron и Vault](https://supabase.com/docs/guides/functions/schedule-functions) · [HTTP-запросы pg_net](https://supabase.com/docs/guides/database/extensions/pg_net)

При обновлении сначала примените актуальную схему к базе согласованного экземпляра, затем разверните новый код с прежними настройками. Для резервной копии облачного экземпляра выгружайте схему `booking` целиком. При `MEDIA_STORAGE=postgres` версии фото входят в тот же дамп.

## Приёмка на Android и iPhone

Для каждого прогона запишите модель, точную версию ОС, браузер и его версию, время записи и получения push, текст уведомления и результат открытия карточки. Используйте стабильный HTTPS-адрес одной витрины.

1. **Клиент на Android и iPhone.** В Chrome на Android и Safari на iPhone откройте публичную ссылку обычной вкладкой. Выберите услугу, дополнения и свободное окно. Подтвердите запись с вымышленным телефоном. Скопируйте приватную ссылку, закройте вкладку и проверьте карточку после повторного открытия.
2. **Кабинет на Android.** Откройте `/admin` в Chrome, войдите и в «Настройках» нажмите «Включить уведомления», затем «Проверить». Подтвердите разрешение в системе и дождитесь тестового уведомления. [Web Push в Chrome](https://developer.chrome.com/blog/push-notifications-on-the-open-web/)
3. **Кабинет на iPhone.** На iOS 16.4 или новее откройте `/admin` в Safari. Нажмите «Поделиться → На экран Домой», откройте кабинет с иконки, войдите и нажмите «Включить уведомления», затем «Проверить». Разрешение подтверждается в системном диалоге. [Web Push на iPhone](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)
4. **Показ и переход.** Для каждого телефона закройте кабинет, заблокируйте экран и оформите отдельный визит с другого устройства. Сверьте услугу и местное время. На экране блокировки должны отсутствовать имя и телефон клиента. Нажатие должно открыть нужную карточку. Повторите переход без действующего сеанса и проверьте, что после входа открывается та же карточка.
5. **Разрешения и два устройства.** Проверьте «Отключить» и повторное подключение на одном телефоне. Запись при двух активных подписках должна появиться на обоих телефонах. Отмечайте отдельно запись очереди, приём push-сервисом и фактический показ на экране.

Если уведомление задерживается, проверьте последние HTTP-результаты задачи в Supabase и состояние доставок. Значение `accepted` подтверждает только приём push-сервисом.

```sql
select id, status_code, timed_out, created
from net._http_response
order by id desc
limit 5;

select count(*) filter (where accepted is not null) as accepted,
       count(*) filter (where accepted is null) as waiting,
       max(attempts) as max_retries
from booking.deliveries;
```

## Vercel и Supabase для личного демо

Vercel Hobby предназначен для личного некоммерческого использования. Для файлового режима нужен постоянный каталог `MEDIA_DIR`. Режим `MEDIA_STORAGE=postgres` хранит обработанные фото в БД. Загрузка через Vercel Functions подчиняется лимиту размера тела запроса платформы. [Vercel Hobby](https://vercel.com/docs/plans/hobby) · [Лимиты функций](https://vercel.com/docs/functions/limitations)

Vercel распознаёт main.py и requirements.txt. Инициализировать отдельную БД Supabase командой `python -m storage` с DATABASE_URL в окружении. Схему booking оставить вне списка схем Supabase Data API. Передать в переменные окружения Vercel DATABASE_URL из панели подключения Supabase (пулер, sslmode=require), ADMIN_HASH, SESSION_SECRET, CRON_SECRET, VAPID_EMAIL, VAPID_PUBLIC и VAPID_PRIVATE из локально созданного .env.

Для обработки очереди в Supabase Cron включить HTTP-вызовы и настроить POST на /jobs/push своего HTTPS-домена раз в минуту. Заголовок Authorization формируется как Bearer и значение CRON_SECRET через Supabase Vault. Обработчик забирает до четырёх доставок за вызов. В Docker тот же обработчик очереди запускается постоянно отдельным процессом. Пометка accepted означает приём push-сервисом. Показ подтверждается наблюдением на телефоне.

## Локальные тесты на Windows

Нужны Python 3.12, Chrome и Node.js с npm. Использовать виртуальное окружение проекта.

```sh
python -m pip install -r requirements.txt pytest httpx playwright
npm install --prefix .local embedded-postgres@19.0.0-beta.20
python tests/run_local.py
```

Каждый прогон открывает свою временную БД с новым паролем и свободным портом. Проверяются HTTP-маршруты, конкурентная запись, повтор запроса, изменение цены, хранение фото в PostgreSQL и клиентская форма в Chrome. Для перехода из push тест генерирует событие в service worker. Отправка во внешний push-сервис в тесте очереди заменена управляемым транспортом.
